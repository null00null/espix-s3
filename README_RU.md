# Linux NO-MMU на ESP32-S3 (N16R8) — Полное руководство







## 1. Введение и обзор проекта







Данный проект представляет собой успешное портирование, сборку и запуск полноценного ядра **Linux 6.11 (NO-MMU)** на микроконтроллере **ESP32-S3** (ревизия N16R8: 16 МБ SPI Flash, 8 МБ Octal PSRAM).







### Архитектурные особенности:



* **Процессор**: Dual-core Tensilica Xtensa LX7 @ 240 МГц (Single-core в текущей конфигурации Linux).



* **Архитектура ABI**: Xtensa FDPIC (Function Descriptor Position-Independent Code), позволяющая исполнять динамически компонуемые программы в физической памяти без блока управления памятью (MMU).



* **Память (RAM)**: 8 МБ Octal PSRAM (физический базовый адрес `0x3d800000`). Из них ~7.3 МБ выделено под ядро, драйверы, кэши SLAB и пользовательские процессы.



* **Постоянная память (Flash)**: 16 МБ Quad SPI Flash. Ядро Linux выполняется в режиме **XIP (Execute In Place)** напрямую из Flash по адресу шины `0x42120000`, сохраняя оперативную память для динамических данных и программ.



* **Сетевой стек**: Двойная архитектура прошивки. Внутренний чипсет управляется прошивкой на базе ESP-IDF (ESP-Hosted), взаимодействующей с ядром Linux через кольцевые буферы разделяемой памяти (Shared Memory IPC). Интерфейс `espsta0` доступен стандартным Linux-утилитам (`iw`, `wpa_supplicant`, `udhcpc`).

## 2. Что было сделано (хронология работы)







1. **Диагностика оборудования**:



   * Определение характеристик подключенной платы: чип ESP32-S3, ревизия Flash 16 МБ, Octal PSRAM 8 МБ, подключение через USB-UART (CH343) на порту `COM3` Windows.



2. **Развертывание среды кросс-компиляции**:



   * Развернуто сборочное окружение в Ubuntu 22.04 LTS (WSL2).



   * Собраны необходимые утилиты (`crosstool-NG`, `kconfig-frontends`, `mtools`, `genimage`, `ninja`, `cmake`, `aria2c`).



3. **Сборка тулчейна Xtensa FDPIC**:



   * Интегрирован модуль `esp32s3.so` (Xtensa Dynconfig) в crosstool-NG.



   * Скомпилирован кросс-компилятор `xtensa-esp32s3-linux-uclibcfdpic-gcc` (GCC 14.1.0 + uClibc-ng).



4. **Сборка загрузчика и адаптера ESP-Hosted**:



   * Настроен ESP-IDF v5.1.1 с поддержкой 8 МБ Octal PSRAM и 16 МБ Flash.



   * Собраны `bootloader.bin`, кастомная таблица разделов `partition-table.bin` и прошивка адаптера `network_adapter.bin`.



5. **Сборка ядра Linux и корневой файловой системы**:



   * Сконфигурировано ядро Linux 6.11-esp32 под Xtensa NO-MMU с драйвером SHM IPC.



   * Через Buildroot собрана корневая файловая система `rootfs.cramfs` (BusyBox, Dropbear SSH, беспроводные и аппаратные утилиты) и перезаписываемый раздел настроек `etc.jffs2`.



   * Сгенерирован образ ядра `xipImage` (3.5 МБ).



6. **Прошивка на физическое устройство**:



   * Все 6 образов перенесены на хост-систему Windows и записаны во Flash через `esptool.py` на скорости 921600 бод.



7. **Тестирование и верификация**:



   * Успешная загрузка ядра, инициализация подсистем, монтирование CramFS и JFFS2, старт системных служб и выход на интерактивную консоль `buildroot login:`.

## 3. Возникшие сложности и их решение







### Сложность 1: Обрывы соединения при клонировании репозиториев (Git / TLS drop)



* **Проблема**: При попытке выполнить `git clone` огромных репозиториев (ядро Linux с многогигабайтной историей ~4 ГБ, ESP-IDF) протокол TLS/GnuTLS в среде WSL2 периодически сбрасывал соединение (`curl (56) / (92) GnuTLS recv error -9`).



* **Решение**: Использование многопоточного менеджера загрузок `aria2c` с параметром `--check-certificate=false` для прямой скачки подготовленных архивов релизных срезов (`tar.gz`) с GitHub. Ядро Linux было распаковано локально, а Buildroot настроен на использование локального каталога через директиву `LINUX_OVERRIDE_SRCDIR` в `local.mk`.







### Сложность 2: Зависимости субмодулей ESP-IDF



* **Проблема**: Система сборки CMake в ESP-IDF жестко требовала присутствия десятков субмодулей из `.gitmodules`, большинство из которых (Bluetooth, Zigbee, MQTT, OpenThread) не нужны для сетевого адаптера ядра.



* **Решение**: Переменная окружения `IDF_SKIP_CHECK_SUBMODULES=1`, точечная догрузка критически важных библиотек (`mbedtls`, `esp-lwip`, `cJSON`, `tlsf`, `esp-phy-lib`, `esp-coex-lib`) и изоляция неиспользуемых компонентов в `CMakeLists.txt`.







### Сложность 3: Ограничения памяти и конфигурация XIP



* **Проблема**: В ESP32-S3 всего 8 МБ PSRAM. Если загружать образ ядра целиком в RAM, памяти на системные процессы и rootfs не останется.



* **Решение**: Использование технологии XIP (Execute-In-Place). Ядро размещено во Flash-памяти и отображено в адресное пространство процессора через шину MMU-кэша (`0x42120000`). Память PSRAM (`0x3d800000`) расходуется исключительно на динамические структуры ядра, стек, SLAB-аллокатор и пользовательские программы.

## 4. Логин и пароль от системы







* **Логин**: `root`



* **Пароль**: **отсутствует** (пустой).







При подключении к консоли введите `root` и нажмите **Enter**.







### Как задать или сменить пароль:



В консоли выполните:



```sh



passwd



```



Введите новый пароль дважды. Раздел `/etc` смонтирован как перезаписываемая файловая система JFFS2, поэтому ваш пароль **сохранится после перезагрузки платы**.

## 5. Доступные команды и утилиты







В системе доступно более 200 команд и апплетов BusyBox:







### ⚙️ Мониторинг и управление системой



* `top` — мониторинг нагрузки на процессор и процессов в реальном времени.



* `free -m` — вывод объема свободной и занятой оперативной памяти (в мегабайтах).



* `ps` — список всех запущенных процессов и их PID.



* `kill <PID>` / `killall <имя>` — завершение процесса по его номеру или имени.



* `uptime` — время непрерывной работы платы и средняя загрузка (load average).



* `dmesg` — просмотр сообщений ядра Linux (лог загрузки, события оборудования).



* `uname -a` — вывод версии ядра и типа архитектуры (`xtensa`).



* `cat /proc/cpuinfo` — детальные параметры процессора Xtensa LX7 (240 МГц).



* `cat /proc/meminfo` — подробная статистика по распределению памяти.







### 🔌 Аппаратные интерфейсы ESP32-S3 (GPIO, I2C, периферия)



* `lsgpio` — отображение списка всех линий GPIO и их текущего статуса.



* `gpio-event-mon` — мониторинг прерываний и входящих сигналов на ножках GPIO.



* `gpio-hammer` — стресс-тестирование линий ввода/вывода.



* `gpio-watch` — выполнение скрипта при изменении состояния пина.



* `i2cdetect` — сканирование доступных шин I2C и обнаружение подключенных датчиков.



* `i2cget` / `i2cset` — чтение и запись регистров I2C устройств.



* `i2cdump` — полный дамп регистров I2C микросхемы.



* `devmem <адрес>` — чтение и запись значений напрямую в физические регистры памяти SoC.

## 6. Пошаговое руководство: Подключение к Wi-Fi и Интернету







Интерфейс Wi-Fi в системе называется **`espsta0`**.







### Шаг 1: Настройка данных вашей Wi-Fi сети



Отредактируйте файл `/etc/wpa_supplicant.conf` с помощью встроенного редактора `vi`:



```sh



vi /etc/wpa_supplicant.conf



```



*Нажмите `i` для перехода в режим вставки, отредактируйте, затем нажмите `Esc`, введите `:wq` и нажмите `Enter`.*







Либо просто запишите конфигурацию одной командой (заменив `MY_SSID` и `MY_PASSWORD` на имя и пароль вашей сети):



```sh



cat << 'EOF' > /etc/wpa_supplicant.conf



ap_scan=1







network={



    ssid="MY_SSID"



    psk="MY_PASSWORD"



    key_mgmt=WPA-PSK



}



EOF



```







### Шаг 2: Подключение к точке доступа



Перезапустите клиент `wpa_supplicant`:



```sh



killall wpa_supplicant



wpa_supplicant -i espsta0 -c /etc/wpa_supplicant.conf -B



```







### Шаг 3: Получение IP-адреса по DHCP



Запустите DHCP-клиент:



```sh



udhcpc -i espsta0



```



Вы увидите сообщение о назначении IP-адреса (например, `192.168.1.125`).







### Шаг 4: Проверка подключения к Интернету



Проверьте доступность внешних серверов:



```sh



ping -c 3 8.8.8.8



```



Проверьте работу DNS (разрешение доменных имен):



```sh



ping -c 3 google.com



```







Если DNS не отвечает, убедитесь, что в файле `/etc/resolv.conf` указан DNS-сервер:



```sh



echo "nameserver 8.8.8.8" > /etc/resolv.conf



```

## 7. Пошаговое руководство: Настройка и подключение по SSH







В системе установлен SSH-сервер **Dropbear**. Хостовые ключи (`dropbear_rsa_host_key` и др.) уже сгенерированы и находятся в `/etc/dropbear/`.







### Вариант А: Быстрый запуск (без пароля)



Если вы еще не задали пароль пользователю `root`, запустите сервер с ключом `-B` (разрешить вход с пустым паролем):



```sh



dropbear -B



```







### Вариант Б: Безопасный запуск (с паролем)



1. Установите пароль для учетной записи `root`:



   ```sh



   passwd



   ```



2. Запустите SSH-сервер:



   ```sh



   dropbear



   ```







### Проверка статуса сервера



Убедитесь, что Dropbear запущен:



```sh



ps | grep dropbear



```



*(Сервер слушает стандартный TCP порт 22).*







### Подключение с вашего компьютера (Windows / Linux / macOS)



1. Узнайте текущий IP-адрес платы:



   ```sh



   ip addr show espsta0



   ```



2. На вашем компьютере откройте PowerShell или терминал и выполните команду:



   ```powershell



   ssh root@<IP_АДРЕС_ESP32>



   ```



   *(Например: `ssh root@192.168.1.125`)*



3. При первом подключении подтвердите добавление ключа хоста, напечатав `yes`.



4. Введите пароль (или просто нажмите Enter, если запущен с флагом `-B`).







### Передача файлов по SCP



С компьютера на ESP32:



```powershell



scp my_file.txt root@<IP_АДРЕС_ESP32>:/etc/



```



С ESP32 на компьютер:



```powershell



scp root@<IP_АДРЕС_ESP32>:/etc/greeting.txt .



```







### Настройка автозапуска SSH при включении платы



Чтобы сервер Dropbear запускался автоматически при каждой загрузке платы, создайте скрипт инициализации:



```sh



cat << 'EOF' > /etc/init.d/S55dropbear



#!/bin/sh



dropbear -R -B



EOF



chmod +x /etc/init.d/S55dropbear



```



Так как каталог `/etc` расположен на JFFS2, этот скрипт сохранится во Flash!

## 8. Карта разделов Flash и перепрошивка







Файлы прошивки и их адреса:







| Файл | Адрес во Flash | Назначение |



|---|---|---|



| `bootloader.bin` | `0x00000000` | Вторичный загрузчик ESP-IDF |



| `partition-table.bin` | `0x00008000` | Таблица разделов |



| `network_adapter.bin` | `0x00010000` | Драйвер Wi-Fi / IPC |



| `etc.jffs2` | `0x000b0000` | Раздел конфигурации `/etc` (чтение/запись) |



| `xipImage` | `0x00120000` | Ядро Linux 6.11 Execute-in-Place |



| `rootfs.cramfs` | `0x00600000` | Корневая файловая система CramFS |







### Перепрошивка в один клик:



Запустите файл [`flash.bat`](file:///C:/Users/user/esp32_linux_bin/flash.bat) из текущей папки.







Либо выполните команду вручную:



```powershell



python -m esptool --port COM3 --chip esp32s3 -b 921600 write_flash 0x00000000 bootloader.bin 0x00008000 partition-table.bin 0x00010000 network_adapter.bin 0x000b0000 etc.jffs2 0x00120000 xipImage 0x00600000 rootfs.cramfs



```







### Подключение к серийной консоли:



```powershell



python C:\Users\user\esp32_linux_bin\terminal.py



```



*(Параметры: 115200 бод, 8-N-1).*
